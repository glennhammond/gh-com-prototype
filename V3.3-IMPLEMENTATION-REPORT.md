# v3.3 implementation report — premium refinement pass

Internal report, not rendered on the public site. Branch:
`feature/rise-storyline-services` (continued from the v3.1 Rise/Storyline
work; no new branch cut for this pass — see note at the end on why).

This was a refinement pass, not a feature: no new sections, no IA changes, no
content removed. Everything below is execution quality — layout, spacing,
copy, interaction, cross-linking — on architecture that was already agreed.

## Starting condition

A separate session shipped a "v3.2" ISQ eLearning Design System feature
directly to `main` while this branch was still open. Before touching
anything, this pass re-audited the whole site to understand what that merge
had changed, since several v3.1 decisions had been superseded:

- `CaseStudy.jsx` gained two new optional section types (`architecture`,
  `components`) and the public `Gaps` panel was removed (`DECISIONS.md` §15).
- The homepage's ISQ section became a dedicated component,
  `FeaturedSystem.jsx`, which already solved "no screenshot exists yet" by
  showing the system's own architecture (a numbered "how it holds together"
  list) instead of a placeholder plate.
- `workIndex.featured` had been reordered to put `isqDesignSystem` first,
  making it the wide **lead card** on `/work` — with no image, it rendered
  through the hatched `GapPanel`, directly under the CASA programme's own
  full-width block. This is very likely what "the ISQ Design System
  placeholder currently weakens the page" refers to.

## Changes made

### 1. Work page
- **Lead card reorder** (`content/projects.js`, `workIndex.featured`):
  Wellbeing Studio (real photography) is the lead card again; ISQ moved to
  the regular grid. Fixes two large, image-less blocks running back to back
  at the top of the case-study tier, without touching the tier structure.
- **Opening copy** (`Work.jsx`): kept "Learning systems in practice." per
  the brief's own endorsement. Rewrote the standfirst to explain *why* these
  six projects were selected rather than list the technologies behind them,
  and moved it into first person to match the rest of the site (`About.js`'s
  own stated rule: "first person throughout... third person is the tell of a
  one-person business pretending to be an agency" — the old standfirst had
  no "I" anywhere).
- **ISQ card treatment** (`ProjectCard.jsx`, `ProjectCard.css`): added a
  fourth card-visual state, `card.map`, rendering a compact numbered list
  instead of the hatched gap plate. This reuses `FeaturedSystem`'s already-
  proven device rather than inventing a new one — same idea, sized for a
  card. Used wherever `isqDesignSystem.card` renders without an image: the
  Work index, and (as a byproduct) the Rise service page's evidence card.
- Programme-tier emphasis reviewed and **kept** at full width —
  `DECISIONS.md` #10 already reasoned through why six years and five
  projects is a different kind of claim. The lead-card swap above was the
  actual fix for "does CASA dominate too much"; the programme block now
  reads as the page's one deliberate emphasis instead of the first of two.
- Spacing audited against `Work.css`'s own tokens; no bug found in the
  tier rhythm itself (see "outstanding" below — this needs a live-browser
  pass to confirm, which this session couldn't get).

### 2. Homepage
- `.specialist` (Rise/Storyline section) now sits on `paper-raised` instead
  of the same `paper` surface as the `.model` section directly above it
  (`Home.css`). The two were visually identical and read as one long block.
- Tightened `specialistDevelopment.standfirst` in `content/home.js` — the
  old line ("Two disciplines inside the practice above, each developed
  further than the model alone shows") restated the section's own existence
  rather than saying anything. New line: "Both sit inside Content and
  Operations above. Neither is a bolt-on."
- `FeaturedSystem` itself was left alone — it's the strongest piece of new
  work in the site and didn't need touching.

### 3. Navigation
- Header/CTA states were already solid (active-state rule not colour-only,
  44px+ targets, sticky, full no-JS fallback). One real gap: the mobile nav
  panel toggled with a hard `display: none` ↔ `block` cut. Replaced with an
  opacity/transform transition gated by the existing global
  `prefers-reduced-motion` handling (`Header.css`) — still out of layout and
  the tab order when closed (`position: absolute` + `visibility: hidden`),
  so nothing changes for keyboard, screen-reader, or no-JS visitors.
- Considered adding a distinct `:focus-visible` treatment to the nav CTA,
  per the plan. **Decided against it** on inspection: the system's whole
  point is one focus treatment sitewide, driven by tokens, and a bespoke
  override for a single component would break that consistency rather than
  improve it. Left as-is.

### 4. Services pages
- Rise page: the evidence card and the "explore the live system" link used
  to read as two unrelated paragraphs. Wrapped them in `.svc-evidence__unit`
  with a hairline top rule on the link, the same "attach a footnote to the
  block above it" convention `.engagement__layers` already uses
  (`RiseDesignSystems.jsx`, `ServicePage.css`).
- Added a cross-link from each service page's CTA to `/services` ("compare
  it with [the other tool]"), and from the Storyline page's evidence section
  to `/work/casa` (the deepest Storyline evidence on the site, previously
  only reachable by scrolling the grid).
- The two-ink-band budget (`svc-principle`, CTA close) was reviewed against
  `CaseStudy.jsx`'s own "ink appears at most twice" rule and found correct
  as built — no change needed.

### 5. Case-study consistency
Ran a full structural audit of all 15 project records
(situation/reframe/decisions/outcomes/figures). Findings:

- `outcomes` was **completely absent** (not just weak) from
  `casaAviationworx` and `casaCatalogue`. Backfilled both, using only facts
  already present elsewhere in each record (`brief.outcome`, confirmed
  scope), with the same honest-disclaimer convention every other
  `outcomes.note` in the file already uses.
- `reflection` (the "what I would do differently" self-critique) exists on
  only 3 of 15 records; `decisions`/`decisionLog` is missing from 6.
  **Deliberately not touched.** Every one of those gaps exists because the
  trade-off genuinely isn't documented anywhere in the source material, and
  every existing file comment in this codebase (`wellbeingStudio`,
  `isqDesignSystem`, the file header itself) treats inventing one as the one
  thing never to do. Recording this here as a known, deliberate gap rather
  than silently leaving it — see "weakest component" below.

### 6. Cross-linking
- Confirmed `relatedSlugs` (`isqDesignSystem` ↔ `connectAndLearn`) is
  already wired into `related()` — no fix needed.
- Storyline page → CASA programme link (above).
- **Real gap found and fixed**: `About.jsx` ended with Contact + LinkedIn
  only, no link anywhere to `/services` — despite being the page most likely
  to be read by someone deciding whether to reach out about a specific kind
  of work. Added one contextual line in `about__contact`.

### 7–9. Microcopy, interaction, CSS hygiene
Folded into the sections above rather than run as a separate sweep, so
nothing got touched twice. Hygiene: removed a double-blank-line artifact in
`ProjectCard.css`; scanned all touched CSS files for duplicate top-level
selectors and 3+ line blank-line runs post-merge — none found.

## Final design audit

**Weakest page**: `/work/casa/aviationworx`. Every image is a placeholder,
`brief.scope`/`brief.outcome` both still carry bracketed gaps, and even
after this pass's backfill its `outcomes` block is the thinnest in the
file — because there is genuinely less confirmed material for this project
than any other. Correctly the thinnest page on the site rather than padded
to look otherwise (`DECISIONS.md` #11 already made this call deliberately).

**Weakest component (pre-existing)**: the case-study `Gaps` panel that v3.2
removed from public view was, before removal, the single biggest tell that
this is a working prototype rather than a finished site — a visible "still
to confirm" checklist on every page. Removing it from public view was the
right call. What replaces it structurally — `reflection` present on 3 of 15
records — is now the site's real remaining consistency gap, and it's
correctly left alone rather than papered over with invented trade-offs (§5).

**Weakest interaction (before this pass)**: the mobile nav panel's hard
`display` cut, fixed in §3.

**Strongest page**: `/work/wellbeing-studio` — real photography, a genuine
three-decision log with stated trade-offs, a testimonial, and an honest
outcomes note. It earned the lead-card slot back in this pass for exactly
that reason.

**Strongest component**: `FeaturedSystem.jsx` (v3.2). It solves "we don't
have the screenshot yet" by making the system's own structure the content,
rather than apologising for an empty box. `ProjectCard`'s new `card.map`
state (this pass) is the same idea, deliberately, scaled down for a card.

**Strongest interaction**: the evidence-figure enlarge dialog
(`Figure.jsx`) — focus trap, Escape, return-focus and a no-JS fallback,
already correct before this pass and untouched here.

## Build verification

`npm run build && npm run verify && npm run audit` — 24 pages, all green.

- JS 139KB gzipped (budget 140) — **one kilobyte of headroom left.** This
  was already a known, recorded regression (`DECISIONS.md` #13, `V3-STATUS.md`)
  from bundling every case-study record into the client tree; this pass's
  content additions (two `outcomes` blocks, service-page cross-link copy)
  used most of what remained. The structural fix (loading case-study records
  per route) is still the right long-term move and is out of scope for a
  refinement pass.
- CSS 12KB gzipped (budget 30), largest image 173KB (budget 180) — comfortable.
- 0 broken internal links, 0 unapproved names, 0 third-party requests outside
  the existing allow-list.
